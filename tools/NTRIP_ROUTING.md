# Independent NTRIP receiver routing

NTRIP A–F share registered raw receiver streams; each output has its own caster, port, mountpoint, password and RTCM message list. Existing configurations default to `main`, reusing the existing TCP source without opening its USB data port. C–F remain disabled until their unit files are installed. Services are not enabled automatically.

Register additional receivers in Settings with a stable `/dev/serial/by-id` data port, input format, baudrate, source ID and unique localhost port. Registration reads metadata only and never sends receiver commands. Septentrio control interfaces are excluded. A missing source prevents activation instead of silently choosing another receiver.

The root input coordinator opens a source only while an active NTRIP service selects it. Consumers share a single passive reader, with bounded queues and localhost listeners. No commands from consumers reach USB. The shared receiver configuration lock and exclusive USB ownership prevent concurrent configuration or another reader. Stop all services selecting a receiver before configuring its profile. Busy or disconnected sources retry after 30 seconds; other sources remain available.

Output units use `ntrip_output_service.py`. It reads the config without evaluating shell syntax, validates the selected route and executes str2str with `-msg` before `-out`. It uses `general.ntrip_ex_binary` when set, otherwise the existing `general.cast` binary. For RTKLIB EX 2.5.1 set `ntrip_ex_binary` to the verified installed EX str2str path during migration; no binary is overwritten by this feature. Do not enable new units until that binary and source ports have been validated. Keep caster passwords out of reports; RTKLIB stream URL delimiters in passwords are rejected rather than silently rewritten.

The unit templates are installed through the existing `tools/copy_unit.sh`. Installation replaces A/B unit definitions and adds C–F and `rtkbase_receiver_streams.service`; it requires a separate reviewed deployment with a backup of the existing units/configuration and `daemon-reload`. This repository change has not been installed on the Pi.

Validation: three physical sources shared to six local consumers passed; six private EX conversions passed, including independent message filtering and valid RTCM CRC. Configuration and production service states/PIDs were unchanged. These tests are short local output tests, not remote caster transmission tests. Local routing, source lifecycle and input fanout tests pass. Actual authenticated Settings-handler tests pass in a private Flask fixture, with service control stubbed. Hardware lifecycle tests of the actual coordinator/input modules also pass: one USB reader per source, shared configuration lock exclusion, source retention for remaining consumers, final USB/lock release, six valid filtered local RTCM outputs and complete cleanup. Active-channel states are provided by the fixture; production unit installation, remote caster transmission and continuous operation remain to validate.
